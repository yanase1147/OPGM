# 水素・都市ガス併合 OPGM モデル

電力システムの最適化モデル **OPGM** を、水素・都市ガス(LNG)・CO2・合成油などのエネルギーキャリアを含む形に拡張したものです。
IBM ILOG CPLEX Optimization Studio の **OPL** で記述されており、線形計画(LP)を基本に、火力の起動停止を MIP として扱うこともできます。

## 概要

- 対象: 電源構成、電力貯蔵、変動再エネ、送電網、分散型エネルギーシステム(水素製造・CCS・DAC・FT合成など)
- 目的関数: システム総費用の最小化(単位: 百万円)
- 費用の内訳: 火力の可変費と起動費、再エネや分散設備の可変費、LFC(周波数調整)費用、CO2 税、輸入LNG費用、設備固定費、水素輸送コスト
- 主な制約:
  - ノード・エネルギーキャリアごとの需給バランス
  - 送電網の潮流制約
  - 蓄電池と揚水の状態遷移(SOC、累積充放電量)
  - CO2 排出上限
  - 合成油の最大・最小量
  - 都市ガス(LNG)の週次供給制約
- 時間軸: 日単位の状態変数を持ち、日内は時間帯分割(`HW`)で表現します。

## 動作環境

- IBM ILOG CPLEX Optimization Studio(ファイルヘッダーは OPL 12.7.1.0 / 12.5 で作成。`main.mod` の `VER` に 12.10 対応の切替あり)
- Excel の読み書き(`SheetConnection`)を使うため、Windows 環境と Excel 連携が使える構成を想定しています。
- 入力データが大きいため、十分なメモリが必要です。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `main.mod` | 実行制御スクリプト。モード選択、CPLEX パラメータ設定、モデル呼び出し |
| `Init.mod` / `Init.dat` | 入力データ(Excel)を読み込み、インデックスや係数行列を初期化 |
| `OPGM.mod` | 最適化モデル本体(変数、目的関数、制約) |
| `OPGM.ops` | CPLEX の設定ファイル(数値重視、内点法アルゴリズム指定) |
| `Report.mod` / `Rep.dat` | 結果集計と Excel(`OutputData*.xlsx`)への出力 |
| `Read.mod` / `Write.mod` | 分解計算用の CPH ファイル(カット・凸包情報)の読み書き |
| `InputData_*.xlsx` | 入力データ(下記参照) |
| `OutputData*.xlsx` | 計算結果の出力先 |
| `data/Boundary.csv` | 境界条件(状態変数の初期値・終端値) |
| `cph/`, `cph_backup/` | 分解計算の CPH ファイル(`cph<日番号>.csv`) |
| `res/` | 計算途中の結果 CSV(`res<番号>.csv`) |

### 入力データ

| ファイル | 内容 |
|---|---|
| `InputData_SYS.xlsx` | 系統全体の設定、エリア、ノード、送電線、CO2 税、時間分割など |
| `InputData_DEM.xlsx` | 電力・ガス等の需要データ |
| `InputData_THP.xlsx` | 火力・原子力発電所(効率、最小出力、起動費、燃料など) |
| `InputData_STO.xlsx` | 蓄電池・揚水などの電力貯蔵 |
| `InputData_CRE.xlsx` | 一定出力の再エネ(水力など) |
| `InputData_FRE.xlsx` / `InputData_FRE2.xlsx` | 変動再エネ(太陽光・風力)の設定と出力時系列 |
| `InputData_DES.xlsx` | 分散型エネルギーシステム(水素・CO2・合成油の変換設備と貯蔵) |

### 出力データ

`Rep.dat` により、次のファイルに書き出されます。

- `OutputData0.xlsx`: 費用、CO2、設備容量、発電量など全体集計
- `OutputData4.xlsx`: 時系列の出力・状態量
- `OutputData5.xlsx`: LFC の上げ・下げ
- `OutputData6.xlsx`: LFC バランス
- `OutputData7.xlsx`: 同期化に関する出力

## 使い方

1. CPLEX Optimization Studio で、このフォルダをプロジェクトとして開きます。
2. 実行構成に `main.mod` を設定します。データファイルは `main.mod` が読み込むため、`Init.dat` などを手動で追加する必要はありません。
3. `main.mod` 冒頭の `MODE` を設定します。
4. 必要に応じて `NHW`、`NN`、`MM` などのパラメータを調整します。
5. 実行します。結果は `OutputData*.xlsx` に出力されます。

パスは相対指定(`data\`、`res\`、`cph\`、`cph_backup\`)のため、作業フォルダをこのディレクトリにして実行してください。

### 計算モード(`MODE`)

| MODE | 内容 |
|---|---|
| 0 | LP ファイル出力のみ(`data/exp*.lp`) |
| 1 | 通期一括(Intertemporal)最適化。全期間を1つの LP として解き、レポートを出力 |
| 2 | 分解法(逐次)。日ごとの小問題を前進・後進に繰り返し解く |
| 3 | 分解法(並列)。全期間を1問題として反復 |
| 4 | 前進計算(ローリングホライズン)。`NN` 日の視野で `MM` 日ずつ進める |
| 5 | レポート作成のみ |

`main.mod` の現在の設定は `MODE=1` です。モードを選ぶと、`Model_*`、`REP`、`DEC` などのフラグは `MODE` に応じて自動で上書きされます。

### 主なパラメータ(`main.mod`)

| 変数 | 意味 |
|---|---|
| `DEC` | 分解計算の有無 |
| `LPF` | LP ファイル生成 |
| `CPH` | カットと凸包による初期解の利用(ホットスタート) |
| `FWD` | 前進(1)・後進(-1)計算 |
| `MIP` | 火力起動停止を整数変数にするか(分解計算では無効化される) |
| `REP` | レポート出力 |
| `BDC` | 境界条件(0: 開放、1: 固定) |
| `ITNR` | CPH ファイルの書き出し間隔(反復回数) |
| `FHW` / `NHW` | 時間集約の設定 |
| `INI` | 初期条件推定のための時間ステップ数 |
| `NN` / `MM` | 前進・後進計算の視野日数と移動日数 |
| `CRO` | クロスオーバーの有無 |
| `VER` | CPLEX バージョン差の切替(1: 12.10) |

## 計算の流れ

1. `Init.mod` が `InputData_*.xlsx` を読み込み、パラメータを初期化します。
2. 分解計算(`DEC=1`)または境界条件固定(`BDC=1`)で `CPH=0` の場合は、まず全期間の問題で初期条件を求め、`cph` に保存します。
3. `OPGM.mod` を選択したモードで解きます。分解計算では日ごとに解き、日間をつなぐ状態変数の価値関数(カット)を更新しながら、目的関数の初日と最終日の差が 1e-5 未満になるまで反復します。
4. `REP=1` の場合、`Report.mod` が結果を集計して Excel に書き出します。

## 注意事項

- 入力 Excel の `InputData_DEM.xlsx` と `InputData_FRE2.xlsx` は約 50 MB あり、読み込みに時間がかかります。
- 分解計算では CPLEX のクロスオーバーを無効にし、双対値(限界価格)を使います。
- `OPGM.ops` と `main.mod` の両方に CPLEX 設定があります。`main.mod` はスクリプト内で `cplex.*` を直接設定するため、値が異なる場合の優先関係は実行環境で確認してください。
- `OutputData*.xlsx`、`res/`、`cph/` は前回計算の出力です。再計算で上書きされるため、必要なら事前にバックアップしてください。
- 一部のソースコメントは文字コードの都合で文字化けしています(`OPGM.mod` の Shift-JIS コメントなど)。
